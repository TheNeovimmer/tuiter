An API explorer that lives in your editor.

  • Neovim ≥ 0.10
  • Pure Lua
  • Zero dependencies
  • Telescope-native

Write requests in .http files, send them with one key, read responses in a floating window. Browsing, history, environments, and collections — all in Telescope, all keyboard-driven. Pure Lua and curl, zero dependencies.

Install→ Quickstart→

§1Overview

tuiter turns ordinary .http files into a full request workspace — parse, send, inspect, organize. Every interaction happens through Telescope pickers, so the whole tool follows your muscle memory for fuzzy finding and multi-selection.

What you can do

  • Execute requests from any .http or .graphql buffer
  • Inspect responses in a tabbed viewer — body, headers, timeline, tests
  • Organize requests into collections and reusable templates
  • Automate with assertions, pre/post scripts, and dynamic variables
  • Secure — OAuth2, bearer, cookies, and secret redaction built in

Design notes

Keyboard-first and zero-dependency. Requests go out through curl over vim.system, so the editor never blocks. The UI prefers Telescope pickers for anything you browse, and falls back to vim.ui.select when Telescope isn't installed.

§2Install

Requirements

  • Neovim ≥ 0.10 — uses vim.system, window titles, vim.json
  • curl on your PATH
  • telescope.nvim for the pickers (falls back to vim.ui.select)

LazyVim / lazy.nvim

Everything loads lazily — cmd on any Tuiter* command, ft on opening a .http / .graphql file. Enable the Telescope extension with require("telescope").load_extension("tuiter").

§3Quickstart

Open a .http file and press <leader>il for the request picker, or put the cursor on a request and hit <leader>is.

The file is the API client. Requests are plain text; send, verify, and commit them with your normal workflow.

§4Telescope

Every surface you browse is a picker — fuzzy-findable, multi-selectable, and sorted by how often and how recently you use things. Six pickers cover the whole tool.

§7Collections & Templates

Collections

Organize requests in *.http.collections/ directories — plain folders, git-friendly, with their own env files. A collection's collection.env.json overrides root-level env files.

Templates

Save and reuse request patterns. Ten built-in templates ship out of the box — GET, POST, PUT, DELETE, auth bearer, pagination, GraphQL, health check, and a login flow. Custom templates are saved under stdpath("data")/tuiter/templates/.

Templates support a {{cursor}} placeholder — the cursor lands there after insertion.

§8Request tags

Tag requests to filter them from any picker. Use a tag: prefix in the prompt.

Typing tag:auth in the request picker narrows the list to requests tagged auth.

§9Configuration

Layout modes

layout = "float" default
Sidebar and response open as floating windows. Fast for spot-checking — send, respond, dismiss.
layout = "split"
Real vsplit panes. A 3-pane layout — [.http] [sidebar] [response] — stays visible while you edit.

Keymap config

Move or drop keymaps with opts.keymaps. Setting one to false disables it; keymaps = false disables them all.
